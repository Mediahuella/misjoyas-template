## Overview

This is a **Shopify theme** for MisJoyas (a Chilean jewelry store), built on the Eurus theme framework. It uses Liquid templating, Alpine.js for interactivity, and Tailwind CSS for styling.

## Commands

```bash
# Start full dev environment (Mix + Shopify theme dev in parallel)
npm run start

# Watch and compile JS/CSS only (Laravel Mix)
npm run dev

# Serve theme from Shopify (without JS/CSS watch)
npm run watch

# Pull latest theme from Shopify dev store
npm run pull

# Push local theme to Shopify dev store
npm run push
```

The Shopify dev store is `misjoyascl.myshopify.com`, environment `development`.

## Build System

- **Laravel Mix** (`webpack.mix.js`) compiles `src/js/main.js` → `assets/main.js` and `src/css/main.css` → `assets/main.css`
- **Tailwind CSS** scans all `.liquid` and `.json` template files; uses `tw-` prefix to avoid collisions with the existing theme CSS
- The `tailwindcss-rem-to-px` plugin converts rem to px with base 16px
- Pre-built theme assets (e.g., `assets/theme.js`, `assets/theme.css.liquid`) are **not** generated by Mix — they are the upstream Eurus theme files and should be edited directly when needed

## Architecture

### Liquid Structure
- `layout/theme.liquid` — master layout; initializes `window.Eurus` global, conditionally loads feature scripts based on theme settings
- `templates/` — JSON templates wiring sections to pages; many variant templates exist per theme style (`breath`, `puff`, `swirl`, `whiff`, `breeze`)
- `sections/` — reusable page sections, each typically has a matching JS file in `assets/`
- `snippets/` — helper partials rendered via `{% render %}`
- `config/settings_schema.json` — defines all theme customizer settings
- `locales/` — i18n strings; `en.default.json` is the source of truth

### JavaScript Pattern
All interactive JS uses **Alpine.js**. The pattern is:

- `Alpine.data('xComponentName', ...)` — registered in per-feature asset files (e.g., `assets/cart-noti.js`, `assets/product-cart.js`)
- `Alpine.store('xStoreName', ...)` — global state shared across components
- Feature scripts are **lazily loaded** via `deferScriptLoad()` in `assets/theme.js`, triggered on first user interaction (`touchstart`, `mouseover`, `scroll`, etc.) — not on page load, unless in Shopify design mode
- The `window.Eurus` global (initialized in `layout/theme.liquid`) holds shared config: slider script URL, cart routes, and a `loadedScript[]` registry to prevent duplicate script loads

### Key Alpine Stores
| Store | Purpose |
|-------|---------|
| `xMiniCart` | Cart drawer open/close, reload state |
| `xCartNoti` | Add-to-cart notification toast |
| `xQuickView` | Quick view modal |
| `xModal` / `xSideBar` | Generic modal and sidebar overlays |
| `xProductRecommendations` | Upsell recommendations in cart |

### CSS
- `assets/theme.css.liquid` — primary theme styles (Liquid-processed for CSS variables from settings)
- `assets/main.css` — Tailwind output (compiled from `src/css/main.css`)
- `assets/page.css.liquid` — page-specific styles
- Tailwind classes must use the `tw-` prefix (e.g., `tw-flex`, `tw-text-sm`)

### Shopify MCP
A `@shopify/dev-mcp` server is configured in `.cursor/mcp.json` — use it for Shopify API lookups and Liquid documentation when needed.

## Separación upstream / personalización

Este repositorio es un fork del tema Eurus. La mayoría de los archivos en `assets/` (ej. `theme.js`, `theme.css.liquid`, `vendors.js`, `splide4.1.3.js`) son código upstream del tema y **no deben refactorizarse ni reestructurarse**; solo se les aplican cambios quirúrgicos cuando es necesario.

Los archivos que son propios del proyecto (se pueden modificar libremente) son:
- `src/js/main.js` y `src/css/main.css`
- `assets/main.js` y `assets/main.css` (output de Mix, no editar a mano)
- Cualquier sección, snippet o template que ya tenga cambios documentados en el branch actual

Cuando un archivo upstream necesite modificarse, hacer el cambio mínimo necesario y dejarlo claro en el commit.

## JavaScript: Alpine.js

- Toda la interactividad usa **Alpine.js**. No agregar jQuery, React, ni otra librería de UI.
- Los componentes se registran con `Alpine.data('xNombre', ...)` y el estado global con `Alpine.store('xNombre', ...)`.
- Los archivos JS de features siguen el patrón de **carga diferida**: se envuelven en el guard `if (!window.Eurus.loadedScript.includes('archivo.js'))` para evitar doble ejecución, y se registran dentro de `document.addEventListener('alpine:init', ...)`.
- No usar `document.ready` ni `DOMContentLoaded` — usar `alpine:init` para registrar componentes/stores, y `requestAnimationFrame` si se necesita acceso inmediato al DOM.

## CSS y Tailwind

- Tailwind tiene el prefijo `tw-`. Siempre usar `tw-flex`, `tw-text-sm`, etc.
- No usar clases de Tailwind sin prefijo; chocan con los estilos del tema upstream.
- Los estilos del tema base viven en `assets/theme.css.liquid` (procesado con variables Liquid desde settings). No duplicar variables CSS de allí en otros archivos.
- Para overrides puntuales en secciones, usar `{% style %}` dentro del propio archivo `.liquid`.

## Liquid

- Las variables de configuración del tema vienen de `settings.*` (definidas en `config/settings_schema.json`). Usar siempre `settings.*` para leer opciones del customizer; no hardcodear valores que el merchant deba poder cambiar.
- Al pasar datos del servidor a Alpine.js, usar `| json` para serializar correctamente y evitar problemas de escape. Ejemplo: `"tags": {{ product.tags | json }}`.
- Los strings de UI deben venir de `locales/en.default.json` usando el filtro `| t`. No hardcodear texto en español en los archivos Liquid (el español va en `locales/es.json`).
- `snippets/` son helpers puros: no deben tener lógica de negocio propia, solo renderizar lo que reciben como parámetros via `{% render 'snippet', param: value %}`.

## Carrito

- El estado del carrito vive en `Alpine.store('xMiniCart')` (definido en `assets/theme.js:1524`).
- Para recargar el carrito después de una mutación, setear `Alpine.store('xMiniCart').needReload = true` — el store se encarga del fetch y del re-render de secciones.
- La notificación de "producto agregado" usa `Alpine.store('xCartNoti')` (definido en `assets/cart-noti.js`). Llamar `$store.xCartNoti.setItem(items)` para disparar el toast.

## Templates y secciones

- Los templates son archivos JSON que referencian secciones por nombre. Al crear un nuevo template, copiar uno existente del mismo tipo (ej. `product.json`) y ajustar los bloques.
- Los grupos de secciones (`*-group.json`) definen qué secciones son sticky (header, footer, aside). No agregar secciones a estos grupos sin entender su impacto en el layout global.
- Las variantes de template por estilo (`.breath`, `.puff`, `.swirl`, `.whiff`, `.breeze`) comparten las mismas secciones; las diferencias son de configuración de bloques en el JSON, no de código Liquid.

## Shopify CLI

- El ambiente de desarrollo es `development` (store `misjoyascl`). El `shopify.theme.toml` **no se commitea** (está en `.gitignore`).
- Usar `npm run pull` antes de editar `config/settings_data.json` para no pisar cambios del customizer.
- Al hacer `npm run push`, los cambios van directo al tema live del ambiente development. Verificar en el preview antes de hacer push a producción.
